# Project Sharing and Portfolio Spec

## Artifacts

- Dev Log: private reflection attached to a lesson completion or project update.
- Project writeup: public text artifact describing what the student built.
- Profile identity: display name only.

## Public Project Writeups

Project writeups are text-only. They are public by default when created through the public project flow, but publishing requires a verified email. Students can edit their writeups. There are no image uploads, video uploads, public discussion threads, public complaint flows, or pre-publication review tools in the product plan.

## Privacy Model

The app asks for username, private email, password, and display name. It does not ask for full name, school, address, precise location, phone number, social handle, or personal contact details. Public pages show display name only.

## Writeup Fields

- Title.
- Short summary.
- Parts used.
- What it does.
- What was tricky.
- What changed during debugging.
- What the student would improve next.

## Portfolio Behavior

A student can see their own private Dev Logs and public project writeups. Public visitors can view published text project pages by URL or gallery listing once that listing is built and complete.

## Risk Note

The chosen product posture favors student control and low friction over platform review. Because public text has no review and no automated scanning, UI copy and data fields must avoid soliciting personal information.
